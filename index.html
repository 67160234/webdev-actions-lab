Exercise 4 & Challenge

Automation & CI/CD Pipeline Analysis

คำอธิบายการทำงานของ GitHub Actions Workflow ด้วยภาษาของตนเอง

Question 1
⚡

Workflow จะเริ่มต้นทำงานเมื่อใด?

ไฟล์การตั้งค่า deploy.yml กำหนดให้ Workflow ทำงานตามเงื่อนไข (Triggers) 2 กรณี ได้แก่:

  • 1. เมื่อมีการ Push โค้ดขึ้นไปที่ Branch main (อัตโนมัติ): เมื่อเราทำคำสั่ง git commit และ git push origin main ระบบ GitHub จะดักจับเหตุการณ์นี้ แล้วเริ่มรันขั้นตอน Deploy ให้ทันทีโดยไม่ต้องทำด้วยมือ
  • 2. เมื่อสั่งรันด้วยตนเอง (Manual Trigger ผ่าน workflow_dispatch): สามารถกดปุ่ม "Run workflow" บนแถบ GitHub Actions ในเว็บไซต์ GitHub เพื่อสั่งให้ Deploy ใหม่ได้ทุกเวลาที่ต้องการ
Question 2
🚀

Job "deploy" ทำหน้าที่อะไรบ้าง?

Job deploy จะเริ่มทำงานบนเครื่องจำลองระบบปฏิบัติการ Ubuntu (ubuntu-latest) โดยดำเนินการตามลำดับขั้นตอน (Steps) ดังนี้:

  1. 1
    Checkout source code: ดึงไฟล์โค้ดล่าสุดจาก Repository ลงมาไว้ในเครื่อง Runner
  2. ★
    [Challenge Step] Verify index.html exists: ใช้ Shell command test -f index.html เพื่อตรวจสอบว่ามีไฟล์ index.html อยู่จริง หากไม่มีจะหยุดการทำงานและแจ้ง Error ทันที เพื่อป้องกันการ Deploy เว็บไซต์ที่พังหรือไม่สมบูรณ์
  3. 2
    Setup Pages: เตรียมความพร้อมและอ่านการตั้งค่าของ GitHub Pages
  4. 3
    Upload static website: แพ็กรวมไฟล์หน้าเว็บ (Path '.') ขึ้นไปเป็น Pages Artifact
  5. 4
    Deploy to GitHub Pages: นำ Artifact ดังกล่าวไปเผยแพร่เป็นเว็บไซต์ออนไลน์จริง พร้อมสร้าง URL ให้อัตโนมัติ
